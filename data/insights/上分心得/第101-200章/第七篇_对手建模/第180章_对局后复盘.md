# 第一百八十章 · 对局后复盘：怎么用 wxq-lab 复盘每一局的对手行为

> **读完这章你能**：跑通「收集→记录→对照→输出」四步复盘流程，单局复盘控制在十分钟内；逐字段填写 matches JSON，把本篇的对手卡、威胁表、跃迁预测、淘汰猜想全部归档；用当日 meta 快照判断你的名次与阵容强度档位是否匹配；把每局的判断误差沉淀为可回测的数据，反向校准 172-179 的全部先验。

---

## 一、复盘为什么必须落在工具上

第 90 章已经讲过复盘的方法与心理——什么时候复盘、怎么面对失误、怎么避免复盘变成自我惩罚。本章不重复那些，本章解决一个更工程化的问题：**复盘怎么落成数据**。复盘的心理关过了、纪律立住了，如果没有一个结构化的容器，每次复盘的产出就还是散在脑子里的几句话，一周之后连「我当时为什么这么判断」都想不起来。

这个问题对本篇格外重要，因为第 171-179 章教给你的所有局内判断——对手卡、阵容识别的时间线、威胁表、跃迁预测、淘汰顺序猜想、二阶博弈——**全部是当场拍的结论**。当场拍结论的判断质量没法自我评估：你不知道你的威胁表是准的还是走运的，不知道你的识别是快还是慢，因为对局一结束，信息流就断了，而人的记忆会自动把结果修饰得合理。复盘工具的作用就是把判断和结果在记忆变质之前钉在一起：**局内你判断了什么（记下来），局外结果是什么（对一下），差距在哪里（写清楚）**。这三步跑过几百局，你的对手建模才从「一套方法」变成「一套校准过的方法」。

这就是 wxq-lab 的定位：它是私人研究工具，不是数据看板。看板给你的是全池统计（data/meta/ 的每日快照），工具给你的是**你自己的对局档案**（data/matches/ 的复盘记录）。两份数据在复盘这一步汇合——你的名次与判断，对照全池的强度与先验，误差就是你下一局的改进方向。本篇把它称为闭环：局内建模（171-179）产生判断，复盘（本章）校准判断，校准过的先验反哺下一局的建模。

项目的数据纪律在 matches 上同样适用。data/ 下的 JSON 是唯一事实源——这条纪律对卡牌库、对快照成立，对你自己的对局记录同样成立：**没落盘的复盘等于没发生**。你脑内记的那点印象不叫数据，叫素材；填进 JSON、带上日期、能被统计的才叫数据。另外，卡牌库每条带 source/verified 字段的习惯，搬到 matches 上就是「记不准的标待补、编不出来的留空」——你自己的档案若掺了编造的字段，一个月后统计出来的先验就是被污染的先验，毒的是你自己的决策。

## 二、四步流程：收集、记录、对照、输出

复盘的标准流程四步，顺序固定，全程目标十分钟以内——超过十分钟的复盘坚持不了每周几十局，工具化的意义就是把单局成本压到可维持的水平。

**第一步：收集（对局结束后立即，约 3 分钟）。** 趁记忆新鲜，把六样东西捞下来：对局结果（名次）、使用的棋手、最终阵容（英雄+等级）、关键天赋、装备分配、关键决策点。还有本篇特别的一项：**对手印象**——谁的阵容、谁淘汰了你、你记得的任何对手行为。对手印象的采集抓三类：行为类（谁缩角了、谁连抢了散件、谁中途转型）、时点类（谁第几回合合成、谁第几回合 all-in）、结果类（谁淘汰了谁、淘汰顺序与你的猜想差多少）。这三类恰好对应 171、175、178 三章的局内判断，采集时就按这个框架抓，记录步骤可以直接对号入座。收集的关键词是「立即」：下一局排队的三分钟里完成粗记，打完三局再回忆第一局的对手，基本上只剩名字和情绪。

**第二步：记录（3-4 分钟）。** 把收集的内容填进 matches JSON（下一节逐字段讲）。记录的原则是**宁粗勿缺**：等级记不清就记大概、天赋记不住名字就记效果描述——字段可以粗糙，空缺没法事后补。

**第三步：对照（2 分钟）。** 打开当日的 meta 快照（data/meta/<日期>/summary.md），做两件事：一是拿强度梯度给你的阵容定档（第五节展开），二是拿榜单核对你的判断（你局内以为的热门和你复盘时看到的热门是否一致——不一致本身就是发现）。

**第四步：输出（1-2 分钟）。** 写死两条纪律：**失误归因最多三条，可执行改进最多三条**。超出的部分按影响力排序砍掉——复盘不是流水账，是把最大的漏洞找出来。改进必须具体到「第 X 回合该做什么」的粒度，「下次注意站位」不是改进，「对刺客阵容的第 20 回合起提前一手缩角」才是。三条结论存进 JSON，完成。

四步里最容易被跳过的是第三步。直觉上「我打完了我知道怎么回事」，但强度是条件概率、直觉是单局样本——你拿第 4 名的这一局，放在强度梯度里可能是三核档（46.6% 前三档）的正常波动，也可能是你执行崩了的信号，不对照数据区分不了这两件事。跳过对照的复盘，本质是用感觉复盘，那不如不复盘。

顺带交代归档的文件纪律：一天多局按 YYYY-MM-DD-<n> 递增编号，不要覆盖、不要合并——合并多局到同一个文件，第七节的跨局统计就得先做拆分手工活，成本转嫁给未来的自己。记录写错不必重写整个文件，改字段即可；但**不要事后润色局内判断**——lineupGuess 收敛慢就是慢，威胁表漏了就是漏了，复盘档案的价值全在真实，修饰过的档案连你自己都骗。

## 三、matches JSON 逐字段讲解

复盘记录落在 data/matches/YYYY-MM-DD-<n>.json，一天多局用序号区分。schema 全字段如下：

| 字段 | 类型 | 填写要点 |
|---|---|---|
| date | 字符串 | 对局日期 YYYY-MM-DD |
| rank | 数字 | 最终名次 1-6 |
| commander | 字符串 | 本局棋手 |
| finalLineup | 数组 | 最终阵容，每项 {hero, level, equip}；equip 是装备名数组 |
| keyTalents | 数组 | 起作用的关键天赋；名称可查 data/talents.json（255 条），拿不准名称就记效果描述 |
| keyMoments | 数组 | 关键决策点，每条带回合号；本篇加上对手相关的时点（谁合成、谁 all-in） |
| opponents | 数组 | 五张对手卡，结构见下一节；本篇的落点字段 |
| conclusions | 数组 | 失误归因，最多 3 条 |
| actions | 数组 | 可执行改进，最多 3 条，具体到回合动作 |

一条完整示例记录（**对局内容为虚构示例**，仅演示填写格式与粒度，数值不作为任何结论依据）：

```json
{
  "date": "2026-09-21",
  "rank": 3,
  "commander": "白歌",
  "finalLineup": [
    {"hero": "露娜", "level": 100, "equip": ["魔律之刃", "聚灵水晶"]},
    {"hero": "孙悟空", "level": 100, "equip": ["无尽巨剑"]},
    {"hero": "太乙真人", "level": 100, "equip": ["近卫荣耀"]},
    {"hero": "吕布", "level": 40, "equip": []},
    {"hero": "甄姬", "level": 40, "equip": ["自然法杖"]},
    {"hero": "杨玉环", "level": 40, "equip": []}
  ],
  "keyTalents": ["2 阶防御向天赋（名称待查 data/talents.json 补录）"],
  "keyMoments": [
    "第 14 回合：对手 A（镜）合成无尽巨剑，按跃迁预测提前缩角，避开一波",
    "第 18 回合：雷鸣刃被对手 C 连抢两个，露娜第二件推迟 3 回合",
    "第 22 回合：对手 B all-in 失败出局，其攒的太乙真人未回收（死亡返还待验证）",
    "第 25 回合：淘汰我的是对手 A，我的缩角被他的强开阵破掉"
  ],
  "opponents": [
    {"commander": "镜", "lineupGuess": "孙悟空完全体线", "equipRoute": "无尽巨剑+聚灵水晶（已兑现）", "positionType": "反应型（3 次确认）", "threatStart": "高", "threatFinal": "最高（淘汰我）", "eliminationRound": null, "notes": "第 19 回合起针对我调站位，二阶博弈我方第 21 回合空转退出"},
    {"commander": "弈星", "lineupGuess": "非主流线", "equipRoute": "散件摊 3 单位（错装信号×2）", "positionType": "静态站桩", "threatStart": "低", "threatFinal": "低", "eliminationRound": 20, "notes": "威胁降级正确，第 20 回合如期出局，淘汰顺序猜想命中"}
  ],
  "conclusions": [
    "对反应型对手 A 的二阶博弈持续到第 21 回合才退出，消耗了 3 回合决策预算且无收益——退出纪律执行晚了",
    "雷鸣刃被连抢后未启动双 fit 线预案，甄姬的自然法杖拖到第 24 回合才合",
    "对镜线阵容的强开形态站位预案缺失，终局被同一方式破阵两次"
  ],
  "actions": [
    "二阶博弈空转一次即退出，改用装备/D 牌层反制（对照第 177 章原则三执行）",
    "选秀被抢散件时，当回合就检查定稿表的第二 fit 线并调整选秀优先级",
    "遇强开阵对手，第 20 回合起站位检查清单里加「主 C 双层保护」项"
  ]
}
```

填写的三个注意点。其一，finalLineup 记**最终**阵容——中盘卖掉转型过的牌不记，否则强度定档（第五节）会被污染。其二，keyMoments 必须带回合号：回合号是复盘时回放战报的索引，也是判断「时点决策对不对」的坐标（第 21 回合的失误和第 26 回合的失误，改进动作完全不同）。其三，opponents 宁可只记两条有把握的，不要五条全是「不清楚」——空字段是诚实的，编造的字段是毒药（项目纪律：绝不编造，查不到就标待验证）。

## 四、opponents 字段：本篇的落点

opponents 是本篇七章的最终落点：第 171 章的对手卡在局内是脑内记号加临时记录，局外的正式归档就在这个字段。每局五张卡（示例里只展开两张演示格式），建议的结构化字段：

| 字段 | 来源章节 | 记什么 |
|---|---|---|
| commander | 第 171 章 | 对手棋手身份（先验的第一通道） |
| lineupGuess | 第 172 章 | 你判断的他的阵容线，以及判断收敛的回合数 |
| equipRoute | 第 176 章 | 他的装备路线与你的跃迁预测命中率 |
| positionType | 第 177 章 | 静态/规则/反应三分型加习惯词条 |
| threatStart / threatFinal | 第 173 章 | 威胁评级的变化轨迹 |
| eliminationRound | 第 178 章 | 实际出局回合（存活就填 null） |
| notes | 全部 | 二阶博弈、卡牌争夺、all-in 时序等行为记录 |

这套字段的设计逻辑是把本篇的每个判断都变成**可对答案的题**：lineupGuess 对照他最终的真实阵容（识别准不准、快不快），equipRoute 对照他实际合成的装备（跃迁预测中没中），eliminationRound 对照你的出局顺序猜想（第 178 章的回测就靠它）。局内你只需要在采样时刻表里记关键词，局后五分钟把关键词扩成字段——归档成本压在这个水平，每周几十局才维持得下去。

与第 171 章的衔接也交代清楚：局内的对手卡分两截，脑内记号负责实时决策（分型标签、习惯词条在局内就要形成），opponents 字段负责局后沉淀。两截的格式刻意保持一致——局内怎么简称、局后就怎么扩写，中间不需要翻译。如果你发现自己在局内记的东西局后看不懂，那不是记忆问题，是局内记号格式的问题，调记号而不是调记性。

跨局复用是归档的回报。第 84 章讲过数据源使用的总原则，落到 opponents 上就是：你自己的五张卡积累几十局之后，就是你私人版的「段位池对手手册」——这个段位池里反应型的浓度、错装的频率、all-in 的典型时点，全是下一局开局的先验。全池统计（data/meta/）告诉你大环境，opponents 告诉你你所在的具体池子——后者只能自己攒，没有捷径。

## 五、对照 meta 快照：名次与强度档位是否匹配

第三步对照的核心动作是**定档**：拿强度梯度的语言给你的这局定位。09-21 快照的梯度（样本量递减=选择偏差的代价，读作凑齐后的条件概率）：仅露娜 24.3% 登顶/58.7% 前三，双核 34.6%/57.8%，三核 46.6%/76.3%，四核 69.3%/93.9%，五核 70.7%/96.7%。

定档之后问一个问题：**你的名次与档位的条件分布匹配吗？** 匹配与不匹配各有诊断价值：

**名次好于档位期望**（比如双核拿了第 2）：先查运气成分——你的前三有没有运气权重（对手撞怪物出局、all-in 恰好失败）？运气占主导的好名次不下结论，防止把幸运当实力（第 86 章的选择偏差在单局复盘里的投影）。若复查后确实是执行贡献（关键对撞全赢、装备路线零断供），把执行亮点写进 conclusions——正面的结论同样是结论，复盘不只找错。

**名次差于档位期望**（比如三核拿了第 6）：这是最有信息量的错配，强度不背锅，执行有问题。逐层查：是阵容成型慢了（对照第 172 章的时间目标，你第几回合才收敛主线）？是装备路线断了没预案（第 176 章的双 fit 线）？是站位被针对（第 177 章你被谁打了两次同一种伤害）？还是 all-in 时点撞车（第 175 章你和他的窗口重叠）？把责任归到具体章节、具体回合，改进才有处落。

**档位本身也要复核**：你自以为的三核，对照快照里这套骨架的当日条件统计——梯度是会动的（09-17 补丁前后同一套骨架的条件概率整体下移过）。定档用当日或最近的快照，不用你背下来的旧数——这也是复盘必须打开 data/meta/<日期>/summary.md 而不是凭记忆的原因。快照因基础设施问题冻结的日子（管道已知问题：聚合榜单曾自 09-20 前冻结数日），对照环节降级为「用最近一期可用快照」，并在记录里标注用的哪一期。

还有一种情况要说破：**名次与档位匹配，复盘也不能跳过**。三核拿第 3，看起来一切正常——但「正常」只说明强度兑现了，不说明执行没有漏洞：你可能靠一次正确的避战少掉两滴血、可能跃迁预测全中省了两次误站，这些正确决策如果不被记录，下局不会被重复；也可能你的第 3 里藏着两个侥幸，档位的条件分布掩盖了执行瑕疵。匹配的正期望名次是最容易复盘走过场的局面，而恰恰是这些局里的细节，构成你稳定发挥的真正底座——conclusions 允许写「本局验证了 X 做法有效」这类正面结论，复盘的产出不只是纠错。

## 六、事后校准清单：本篇各章的对答案环节

复盘的对手行为部分，按本篇各章逐一对答案。每局过一遍这张清单，每条只花十几秒：

- **谁淘汰了我，我的威胁表里有他吗？** 淘汰你的对手不在你的威胁名单前二，说明威胁评估（第 173 章）有盲区——盲在哪个因子，实力差、克制还是碰撞概率？
- **我的阵容识别哪一步慢了？** 对照第 172 章的时间线：他第 3 回合的先验信号（棋手身份）你读到了吗，第 5 回合的主候选你排对了吗，第 10 回合你收敛的结论和他最终阵容差在哪？lineupGuess 字段里记下你实际收敛的回合数，几十局之后你的识别速度分布就出来了——平均值是多少、什么类型的线收敛最慢，都有数。
- **卡牌争夺的决策对不对？** 第 174 章的抢/让决定事后看：你抢的件最后用上了吗，你让的核如果抢了会怎样？只记结论不懊悔——决策质量的评价标准是当时信息下的期望，不是事后结果。
- **all-in 谁先谁后？** 第 175 章：你的 all-in 时点与他的窗口是错峰还是相撞？被迫提前 all-in 的诱因是什么回合埋下的？
- **装备路线预测命中几条？** 第 176 章：opponents.equipRoute 里记的预测，命中与否各记一笔，命中率低的线（比如你总把宽线当窄线）定向补。
- **出局顺序猜想的回测。** 第 178 章：猜对的顺位有几个、错判的主因子是哪个——连续几局错同一个因子，就是你的读数短板，下局的 20 秒投资向它倾斜。

清单的用法有一个细化：每一条校准的产出都写到 opponents 的 notes 或 conclusions 里，哪怕只有半句话。「威胁表盲区：漏了碰撞概率因子，他在我对角三回合没警觉」——这种粒度的记录，攒十局之后能直接看出你的系统性偏差在哪里；而只写「威胁评估不准」这种粒度，攒一百局也看不出东西。校准记录的粒度决定它的复利，值得为半句话多花十秒。

清单过完，失误与改进已经自然浮出，第四步的三条归因三条改进从中挑最大的就行。注意校准与心理的分工（第 90 章）：清单负责找出「哪里错了」，心理建设负责「错了之后怎么不被 tilt 拖进下一局」——两件事都要做，但别混在十分钟里做，后者放在复盘之外的时间。

## 七、长期积累：从对手卡到段位池先验

单局复盘是即时反馈，opponents 字段的更大价值在**跨局积累**。几十局之后，你的 data/matches/ 目录里躺着的就不是一个一个孤立的 JSON，而是一份可以统计的样本：这个段位池的对手里，静态站桩型占多少、反应型占多少；缩角习惯的出现频率；all-in 的典型回合段；错装率多高；「镜」「白歌」这类棋手在你池子里的实际出场与威胁构成。这些统计反哺本篇各章的先验：第 172 章的棋手-路线对应表、第 177 章的习惯辞典频率、第 178 章的六因子权重，全部可以用你自己的池子数据重新校准——书里的先验是通用先验，你的池子有你的池子的脾气。

积累的纪律两条。其一，**样本量门槛**：第 69 章立过的规矩原样适用——方向性的观察也要攒够样本再下结论，几十局看趋势，上百局谈规律；单看十局就断言「我的池子爱缩角」，和拿一天榜单定 meta 是同一种错误。其二，**快照日期与版本标注**：跨局的统计要记录时间跨度与版本（补丁会改行为——花木兰被削的版本，缩角频率都可能变），跨版本的统计分开算或者明确标注混合口径，别让版本噪声混进习惯统计。

这份个人数据还有一个更结构化的去处：第 194 章会讲怎么用 matches 数据构建你自己的棋手×阵容矩阵——全池的棋手统计告诉你孙小宾在谁手里是 72.5%，你的个人矩阵告诉你「你」用哪个棋手的掌握度最高。全池条件统计与个人条件统计的关系，就是地图与足迹的关系：地图告诉你哪里富庶，足迹告诉你你实际走到了哪里。两份都看，才知道差距是路线问题还是脚力问题。

这份积累最终汇回项目的大闭环：局内判断（171-179）→ 复盘归档（本章）→ 个人统计 → 修正先验 → 更准的局内判断。第 98 章讲过工具构建的原则，第 99 章讲过教学相长——本章的 opponents 归档就是这两条在对手建模上的落地形态：工具替你记住一切，你只需要每局花十分钟对答案。积累的启动没有仪式感：下一局打完，新建一个 JSON，填上今天这个日期——闭环从第一局开始转，转满一百局，你手里就有一份整个段位池里绝大多数玩家都没有的资产。

## 八、落到执行：本章的决策出口

1. **每局结束十分钟内走完四步**：排队三分钟粗记收集、四分钟填 JSON、两分钟对照当日快照、两分钟写三条归因三条改进——超过十分钟的复盘做不长久，先保住节奏再保住深度。
2. **opponents 每局归档，字段按第四节七项填**：宁缺毋假，识别不准就写「不确定」，关键字段是 lineupGuess 的收敛回合、equipRoute 的预测命中、eliminationRound 的实际值。
3. **定档只用当日或最近可用快照**：名次与档位错配时，好于期望先查运气、差于期望逐层查执行；快照冻结的日子标注所用期数。
4. **校准清单每局过一遍**：威胁盲区、识别慢点、争夺决策、all-in 时序、装备预测、淘汰猜想六项对答案，连续错同一项就定向补那一课。
5. **统计跨局攒、结论等样本**：几十局看趋势、上百局谈规律，跨版本口径分开；你的段位池先验只认你自己攒的数据。
6. **复盘只管对错、不管情绪**：tilt 处理放在复盘流程之外（第 89 章），十分钟的工具时间不被心理时间侵占。
